К стати о параллельности, Дипсик позводяет назначить несколько ключей API доступа, и если верна моя догадка о том, что каждому ключу доступа соотвествует отдельный экземпляр KV кеша, то тогда есть смысл чтобы агент ходил по нескольким разным ключам держа таким образом несколько разных экземпляров больших контекстов, каждый собранный под свою специфику и задачу. 

Хотя если даже в рамках одного ключа доступа будет один общий KV кеш на несколько ключей, то ведь можно сделать несколько параллельных аккаунтов у которых точно будут разные экземпляры KV кеша.
