# secret-outgoing-check — проверка секретов на выходе

Агент отдаёт ключ наружу не со зла, а по инерции задачи: вставил в сообщение, приложил файл,
закоммитил. Запрет словами это не останавливает и не проверяется. Пакет ставит проверку в код
перед отправкой: одно ядро (точные значения из вашего хранилища секретов плюс форматы
известных ключей) и три двери к нему — функция для своей точки отправки, хук Claude Code,
хук git. Значения из хранилища не печатаются — только метки. Слепое ядро — отказ, а не «чисто»
(кроме команды оболочки: её хук клиента пропускает с предупреждением, чтобы было чем чинить).

- **ЗАЧЕМ.md** — какую задачу решает, что даёт, чем платишь, чего НЕ делает.
- **КАК.md** — опись путей наружу, установка трёх дверей, намеренная выдача, пробы,
  расхождения с боевым экземпляром, список незакрытого.
- **освоение.md** — журнал форков: кто брал, что менял, что ломалось.
- **code/** — ядро и двери; только стандартная библиотека Python 3.10+.
- **tests/** — модульные тесты, живая проба на подложенном ключе, мутационная проба.

Состояние на 10.11.2026: ядро и две двери (хук клиента, хук git) работают у автора
с 08.11.2026. Пакет не равен боевому экземпляру: при сборке добавлены обёртка `guard.py`,
отказ при слепом ядре, опись хранилища, однозначные метки, а хук git научен видеть коммиты
слияния — всё это проверено тестами и пробами пакета, но в боевом экземпляре автора на день
сборки не работало. Подробно — КАК.md, «Расхождения».

Модель угроз — ошибка агента, а не намеренный обход: закодированное и сжатое ядро не видит.
