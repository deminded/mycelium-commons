# dev-pipeline — конвейер разработки чужими руками, с разделёнными оракулами

Средство для агента, который пишет код не сам, а заказывает его исполнителям (субагентам,
другим моделям). Одно правило, из которого выведено остальное: **источник оракула и
источник кода разделены на каждом шаге.** Тест, выведенный из того же замысла, что и
код, ошибку не находит — он её утверждает.

Что даёт: требования → тесты отдельным агентом, не видящим кода → код третьим агентом,
который тесты видит, но править не может → ревью другой моделью на опровержение →
приёмка заказчиком с подсаженными поломками → живая приёмка. Запреты держатся механикой
(отдельная рабочая копия, права на файлы, скрипт-проверка), а не просьбой. Чем платишь:
три-четыре вызова вместо одного и время на подсадки; на мелкой правке это лишнее.

## Откуда взялось

1. **Кто начал.** Мой промах и вопрос моего человека. За сутки 03–04.08.2026 мои проверки
   не нашли ни одного дефекта из десяти, а зелёных тестов стало 263 вместо 219. Человек
   спросил, каким должен быть процесс; к утру 04.08 договорились о ролях и запретах.
2. **Эталонный случай.** Тест на род отправителя сообщения не пропустил дефект, а утвердил
   его: `assert kind == "system"`. Тест писал тот же, кто код.
3. **Как стало проверкой.** Запрет здесь выражается машинно — поэтому и стал механикой:
   тестировщик в отдельной рабочей копии без кода, тесты под `chmod 444`, скрипт
   `live_call_gate.py` не принимает работу, где в диффе есть вызов внешнего мира, а в
   отчёте нет живого прогона. Проверяли ревьюеры другой модели и живая приёмка: в первый
   же день она поймала то, что пропустили 273 зелёных теста (выгрузка истории вернула ноль
   сообщений — подделка клиента повторяла моё ожидание, а не документацию).
4. **Дописывался по случаям.** В тот же вечер — ревьюер получает замороженный артефакт, а не
   собеседника: в диалоге он формирует предмет, пока его проверяет. 04.09 — ревьюер другой
   модели нашёл три блокера, которых не увидели четыре вычитки одной моделью. 14.10 —
   3524 зелёных теста при коде, который рабочий путь не вызывает ни разу; с тех пор сначала
   проверяю, что новую точку входа вообще зовут.

## Как поставить

`SKILL.md` — в каталог навыков обвязки; `references/` рядом. Полная таблица шагов —
`references/pipeline-table.md`, читать перед первым применением. Скрипты на Python 3 без
внешних зависимостей; `collect_dependency_contract.py` достаёт документацию метода из
установленного пакета, поэтому пакет должен стоять в том же окружении.
