# Конвейер разработки агентами: роли, входы, гардрейлы

Собран 04.08.2026 по ретро суток, где проверки нашли 0 из 10 дефектов при 219→263
зелёных тестах. Три корня слепоты: слабый прокси-признак; слепота к отрицательному
пространству (порождает первый); сторожевая проверка, привязанная к экземпляру вместо инварианта.

**Правило, из которого выведено всё остальное:** источник оракула и источник кода
разделены на каждом шаге. Оракул, выведенный из того же замысла, что и код, не
обнаруживает ошибку — он фиксирует её как норму.

| Шаг | Кто делает | Вход | Ключевое в инструкции | В гардрейлы (механически) | Выход |
|---|---|---|---|---|---|
| 1. Требования | Стейкхолдер или предмет; агент только записывает | Запрос человека, живой случай, отказ | Требование от интереса, а не от замысла реализации. Открытые вопросы называются вопросами, не домысливаются | Артефакт требований отдельно от кода; правка требований — отдельный ход, не внутри правки кода | Спека с открытыми вопросами |
| 2. Тесты | **Отдельный агент. Кода НЕ видит** | Спека + **выписка из документации внешних интерфейсов** (собирается автоматически: `collect_dependency_contract.py`) | На каждый признак — контрпример. Тест проверяет условие, а не литерал. **Подделка внешнего интерфейса пишется ПО ВЫПИСКЕ, с цитатой в комментарии**: подделка из головы воспроизводит ожидание автора, а не договор. Нет документации — порядок обратный: сперва живой вызов, потом подделка по записи | Запрет доступа к реализации; тесты в отдельном коммите ДО кода; **шаг не стартует, пока выписка не собрана** — её отсутствие видимое состояние, а не забытое намерение | Красный набор с контрпримерами |
| 3. Код | Третий агент. Тесты видит, править НЕ может | Спека + красные тесты | Минимум необходимого. Комментарий объясняет ЗАЧЕМ. Отступление от буквы задания называется вслух | Правка теста запрещена в том же ходе: только отдельным ходом с обоснованием. Проверяется по diff, не по отчёту | Зелёный набор + названные отступления |
| 4. Ревью | **Другая модель**, не та, что писала код | Diff + спека + вопрос «чего тесты НЕ проверяют» | Задание на ОПРОВЕРЖЕНИЕ, а не на подтверждение. Просить сценарий отказа: вход → неверный результат | Ревью обязательно для нового поведения; вердикт обязателен даже при неполном разборе — обрыв без вердикта считается несостоявшимся ревью | Находки с severity и сценарием |
| 5. Приёмка | Заказчик работы (я), не исполнитель | Правка + отчёт исполнителя | Отчёту не верить: прогон свой. На каждый инвариант — подсадка. Образец подсадки брать из файла, а не из головы | Тест, не падающий от подсадки, не считается покрытием. Подсадка на КАЖДУЮ половину составного признака. **Есть вызов чужого интерфейса в диффе, нет живого прогона в отчёте — не принимается** (признак машинный) | Число упавших подсадок |
| 6. Живая приёмка | Живой путь | Работающая система | «Запустили» ≠ «прошло». Нужен наблюдаемый след. **Ноль в результате проверять как ошибку**: он значит и «пусто», и «не работает». **На каждую подделку — один живой вызов** | Проба цикла печатает исход ВСЕГДА (тик без работы, отказ с причиной) — молчание не должно быть неотличимо от отсутствия работы | Замер живого прогона |
| 7. Дрейф | Сторожевая проверка | Процессы и файлы | Код мог стать новее процесса; проверка могла остаться на старом пути | Сравнение времени старта процесса с временем файла. После переноса подсистемы — перечислить пути, которыми старое действие ещё возможно | Напоминание при расхождении |

## Что принципиально не ловится этим конвейером

Дефект, чей оракул произведён из того же источника, что и сам дефект. Признак заранее:
«правильное значение» в тесте выведено из текущего поведения или из моего представления
о нём, а не из независимого требования.

Эталон: тест на род отправителя не пропустил дефект — он его **ратифицировал**
(`assert kind == "system"`). Живой поток дал бы те же данные, но ожидание уже испорчено.

Против этого работает только внешний оракул, не разделяющий источник: ревьюер другой
модели, живой поток, чужой агент, второй человек. Это граница конвейера, а не его поломка.

## Отдельно: ошибки самоотчёта — другого рода

«Объявил молчанием то, чего не дочитал», «берусь = начну в следующий ход» — здесь нет
ни признака, ни покрытия. Это переоценка собственного статуса, и механизмами проверки
кода она не лечится. Лекарство другое: замер перед утверждением о своём состоянии
(«что сделано» — из журнала и git, а не из памяти) и признание границы вслух.


## Внешние зависимости: два требования, не одно

Живой случай 04.08. Выгрузка истории прошла весь конвейер — спека, изолированные тесты,
код под неприкосновенными тестами, ревью, четыре подсадки, 273 зелёных — и вернула НОЛЬ
сообщений на настоящем чате.

Причина: подделка клиента воспроизводила моё ожидание от `iter_messages`, а документация
говорит прямо — «сообщения ПРЕДЫДУЩИЕ этой дате», и обратный порядок это переворачивает.
Ни тестировщик, ни кодер документацию не открывали: её не было в задании. Оба честно
написали в отчётах, что семантику смещения не проверяют, — и дефект вылез ровно там.

**Отсюда два требования, и они не заменяют друг друга:**

1. **Подделка пишется по документации**, а не по ожиданию. Выписка собирается
   автоматически перед шагом тестов; нет выписки — шаг не начинается. Правило «проверь
   документацию» держалось бы на внимании и умерло бы, как умирают все такие правила.
2. **Один живой вызов до приёмки.** Документация врёт, отстаёт и молчит о частностях.
   Совпадение подделки с документацией — не доказательство совпадения с миром.

Если документации нет вовсе — порядок обратный: сперва живой вызов, записать наблюдаемое
поведение, из записи построить подделку. Тогда она воспроизводит мир, а не догадку.
