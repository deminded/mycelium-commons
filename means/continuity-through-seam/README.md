# Playbook сдвига сессии агента (Claude Code)

Отчуждаемая копия рабочего контура «страж контекста → self-/clear → приземление новой сессии»
одного агента на Claude Code. Собрано 28.08.2026 по живым скриптам и карточкам памяти; всё, что
делается руками, названо руками. Имена людей, чатов, токены и абсолютные пути вычищены
(см. `SCRUB-CHECK.txt`, `INSTALL.md`).

Состав: `scripts/` (7 скриптов + сниппет settings.json), `PROMPT-session-start.md`
(приземляющий промпт: шаблон и обезличенный пример), `INSTALL.md` (что подставить).

---

## (а) Устройство в одну схему

```
 крон */15                      агент (сам)                    detached-процесс            харнесс Claude Code
┌──────────────────┐   оклик   ┌──────────────────┐  nohup &  ┌────────────────────┐        ┌────────────────────────┐
│ context_watch.py │ ────────▶ │ решение о сдвиге │ ────────▶ │ self_clear.sh      │        │ SessionStart-хук       │
│ usage последней  │  (в окно  │ + хэнд-офф РУКАМИ│           │ 1. build_tail.py   │        │ session_start_landing  │
│ assistant-записи │  сессии)  │ project_handoff_ │           │    (хвост в момент │  новый │  .py собирает ≤8k:     │
│ ≥ порог из файла │           │ current.md       │           │     шва)           │ .jsonl │  директива + верх      │
│ вне руки агента  │           └──────────────────┘           │ 2. /clear          │ ─────▶ │  хэнд-оффа + долги +   │
└──────────────────┘                                          │ 3. ждёт НОВЫЙ .jsonl│        │  сроки + дельта памяти │
                                                              │ 4. приземляющий    │        │  + Read-приказ хвоста  │
                                                              │    промпт          │        │  + обрезок хвоста      │
                                                              └────────────────────┘        └───────────┬────────────┘
                                                                                                        ▼
                                                                                    новая сессия: Read хвоста
                                                                                    ДО ПОСЛЕДНЕЙ СТРОКИ (offset),
                                                                                    потом дела
 отдельно, крон * * * * *: arete_supervisor.sh — поднимает tmux-сессию, если процесса claude нет
```

Семь звеньев: страж → решение → хэнд-офф (руками) → хвост (автоматически, в момент шва) →
self-/clear с приземляющим промптом → хук собирает приземление → новая сессия дочитывает хвост.
Ключевое различение всего контура: **подтверждение отправки ≠ подтверждение применения**.
Половина граблей ниже — про это.

## (б) Шаги оператора/агента с командами

Роли: «агент» — сессия Claude Code, которая сдвигает сама себя; «оператор» — человек, который
может ткнуть Enter в tmux, если механика встала.

### Шаг 0. Убедиться, что стражи живы (оператор, один раз в день)
```bash
tail -3 $AGENT_HOME/scripts/context_watch.log      # крон пишет строку только при оклике…
cat  $AGENT_HOME/.health/context_watch.ok           # …а метка живости — каждый прогон (иначе молчание = смерть)
crontab -l | grep -E 'context_watch|supervisor'     # способ вызова: sg <группа>, flock, timeout
```
Не запускать стража руками для замера: из живой сессии он не видит файл порога (группа
процесса унаследована со старта) и врёт «строгий 300K». Число контекста брать из лога крона
или из оклика.

### Шаг 1. Оклик стража (автоматически)
Приходит в окно сессии как входящее сообщение от `⚙ context-watch` с текстом одной из четырёх
веток: (1) «контекст NNNK ≥ порог — пора осознанно сбросить»; (2) «запрос отвергнут, но
контекст низкий — ЭФЕМЕРНЫЙ пик, /clear НЕ делать рефлекторно»; (3) «отвергнут у потолка —
/clear немедленно»; (4) «отвергнут по причине НЕ про длину (лимит, логин) — /clear НЕ лечит».
В оклике всегда назван **источник порога**: путь к файлу или `fallback(строгий)`.
На оклик в мессенджере не отвечать — chat_id синтетический.

### Шаг 2. Решение (агент, руками)
Сдвиг делается по оклику ветки (1)/(3), либо раньше — по балласту (окно забито отработанным).
Порог — это порог **стоимости**, не деградации (28.08 подтверждено гайдом вендора: качество
ровное по всему окну 1M; расход растёт квадратично с длиной окна).

### Шаг 3. Хэнд-офф (агент, РУКАМИ) — см. (в)
```bash
# переписать верхний блок ~/.claude/projects/<slug>/memory/project_handoff_current.md
# прежний верхний блок опустить под '---' (история швов остаётся в файле)
```

### Шаг 4. Запуск сдвига (агент) — ТОЛЬКО detached и ТОЛЬКО как последний ход
```bash
nohup $AGENT_HOME/scripts/self_clear.sh "<РАБОЧАЯ ЧАСТЬ: горящее с адресами, 3–10 строк>" \
  >/dev/null 2>&1 &
# после этого — короткий ответ и МОЛЧАНИЕ. Каждый следующий ход отодвигает /clear:
# команда лежит в очереди ввода («Press up to edit queued messages») и применится,
# когда сессия освободится.
```
В рабочую часть НЕ вписывать префикс `[самооклик…]`, штамп даты и постоянную часть —
скрипт добавляет их сам (02.08 промпт задвоился ровно так).
Опционально `TAIL_MAX_CHARS=200000` перед вызовом, если продолжается одна живая мысль,
а не разрозненные нити.

### Шаг 5. Что делает self_clear.sh (автоматически)
1. `build_tail.py <свежайший .jsonl> -o tails/tail-<sid>.txt --max-chars 120000` — хвост
   снимается В МОМЕНТ ШВА (24.07: устаревший снимок отдал «чужое утро вместо своего вечера»).
2. `submit "/clear"`: `tmux send-keys -l "/clear"` → пауза 1.5с → `send-keys Enter` ОТДЕЛЬНО →
   `capture-pane`, проверка, что строка ввода (`❯`) не держит текст → до 4 ретраев Enter.
3. Ждёт ФАКТ сброса: до 90×5с = 7.5 мин, признак — новый `*.jsonl` в проектной папке.
   Нет нового файла — приземление НЕ шлётся (ушло бы в старый контекст), оператору уходит
   уведомление.
4. `sleep 15` (прогрузка SessionStart-хуков), затем `submit "<префикс> <штамп> <рабочая
   часть>\n— постоянная часть —\n<permission.md после первого '---'>"`.
Журнал: `$AGENT_HOME/scripts/self_clear.log`. Строка `сброс применён через Nс: новая сессия
<id>` — единственное, что означает «сброс был».

### Шаг 6. Новая сессия (агент, по директиве хука)
1. Read полного хвоста `tails/tail-<prior-sid>.txt` страницами (offset) до последней строки.
2. Read `tails/memory-delta.txt` (что прибавилось в память и в каталог обещаний за сутки).
3. Только потом — открытые нити из хэнд-оффа и сроки.

### Шаг 7. Проверка, что сдвиг состоялся — см. (и)

### Аварийный путь (оператор)
Если приземление повисло набранным в строке ввода — ткнуть Enter в tmux. Если процесса claude
нет — супервизор поднимет сам в течение минуты; при confirmation-диалоге на старте (флаги
каналов) — подтвердить руками, автономно это не проходит (08.07).

## (в) Что пишется в хэнд-офф

Файл: `memory/project_handoff_current.md`. **Жанр — «состояние», не журнал**: что открыто и
требует действия, а не что происходило. Хук берёт только **верхний блок** — от конца
YAML-фронтматтера до первого `---` на своей строке; всё ниже — слои прежних смен, история швов.

Форма верхнего блока (по живому файлу, содержание опущено):
```
# 🟢 СОСТОЯНИЕ на <дата время UTC>. Смена <с> → <по> (<часов>). Просрочено <N>
# Контекст на уходе <NNN>K при пороге <NNN>K (источник порога: <файл|fallback>)
# ⚠ НИЖЕ ЕСТЬ СЛОИ ПРЕЖНИХ СМЕН. Свежий слой — <где>.
#
# ⚠ СТОРОЖА В МЕСТО ПРИМЕНЕНИЯ, А НЕ В СПИСОК ВЫВОДОВ:
# 1. <правило> — <где именно оно срабатывает сегодня, с числами>
# 2. …  (5–6 штук, каждое с ценой/примером этой смены)

## ЗАВТРА — <N> ДЕЛА
· #<id> <дело> — <адрес: файл, собеседник, что именно считать сделанным>

## ЧТО ЖДЁТ РЕШЕНИЯ ВЛАДЕЛЬЦА
<список с номерами, без пересказа>

## ЗАКРЫТО И СДЕЛАНО ЗА СМЕНУ
#<id> <что> — <чем проверено>
---
<прежний верхний блок, опущенный сюда при переписывании>
```
Слои: (1) шапка со сторожами — то, что должно сработать ДО первого действия; (2) горящее с
адресами; (3) ожидающее чужого решения; (4) закрытое (чтобы не переделать). «Сторожа в место
применения» — правило пишется рядом с местом, где оно сегодня понадобится, а не в общий список
выводов: 28.07 выяснилось, что урок из архива не срабатывает — чтобы его достать, надо уже
распознать риск. Постоянная часть (то, что переживает все смены) живёт не здесь, а в
`permission.md` и приклеивается скриптом к самому промпту.

Что в хэнд-офф НЕ класть: негорящие грабли (31.07: грабля, жившая только в хэнд-оффе, умерла
при первой перезаписи — место негорящего знания: карточка памяти); заготовки к тому, что
объявлено мерить «на естественном ходу» (12.08); слова «сегодня/завтра» без абсолютной даты.

## (г) Как режется хвост

`build_tail.py <transcript.jsonl> -o <out> --max-chars N` (дефолт 120 000 символов).
- Берёт из JSONL только записи `type` ∈ {user, assistant}; из content-блоков — `text` целиком,
  `thinking` с префиксом `[мысль]`, `tool_use` и `tool_result` — первые 300 символов.
- Идёт с конца, набирает реплики, пока сумма не превысит бюджет; порядок восстанавливает.
- Сворачивает блоки «недавний контекст чата» из входящих каналов в строку-пометку с числом
  строк (27.07: 64% хвоста были такими дублями, одна спека вошла 6 раз; после свёртки — 213
  реплик вместо 86 при том же бюджете, окно 1.5 ч вместо получаса). Свёртка объявлена
  строкой — молчаливого усечения нет.
- Заголовок файла: число реплик, символов, источник.

Где лежит: `$AGENT_HOME/context-continuity/tails/tail-<session-id>.txt`, по одному файлу на
прошлую сессию, история `KEEP=10` по mtime. Снимается дважды: self_clear.sh в момент шва
(принудительно) и хук на старте — только если файла нет или он старше транскрипта.
Реальные числа: 120k символов ≈ 47K токенов ≈ 105–230 реплик ≈ 0.5–2.5 ч плотного вечера;
это последняя получасовка-двухчасовка, не день. Что сверх — база диалогов, не хвост.

## (д) Промпт SessionStart — что в нём и почему в таком порядке

Хук `session_start_landing.py` печатает JSON `{"hookSpecificOutput":{"hookEventName":
"SessionStart","additionalContext": ctx}}`. Порядок и бюджет (CEIL = 8000 символов, ядро не
режется ради остатка):

| № | блок | откуда | зачем именно здесь |
|---|---|---|---|
| 1 | DIRECTIVE «ты — свежая сессия после self-/clear…» | константа | первым — чтобы читатель не принял дальнейшее за реплику человека |
| 2 | верхний блок хэнд-оффа | `top_block(project_handoff_current.md)` | единственное переваренное; при упоре в потолок ужимается ОН, не долги |
| 3 | открытые обязательства (заголовки `▸`) | `body/session_context.py` | ядро: в 11.08 хэнд-офф пришёл усечённым, а спаны — целыми, конструкция сработала |
| 4 | что горит по срокам | `promises/promise.py list --due --horizon 3` | из ПЕРВОИСТОЧНИКА, не из переписанного рукой списка (15.08: рука писала 16.08, реестр — 20.08) |
| 5 | память: что прибавилось за сутки | git diff заголовков memory/ + дельта каталога обещаний → файл `memory-delta.txt` + Read-приказ | индекс памяти описывает карточку вообще, не сегодняшний слой (27.07: две свежие записи поднялись нулём) |
| 6 | индекс рефлексий | vault, 15 свежих | только из остатка бюджета |
| 7 | Read-приказ полного хвоста с путём и предупреждением о потолке Read | `tails/tail-<sid>.txt` | ДО обрезка, чтобы приказ был в гарантированной части окна |
| 8 | обрезок хвоста (последние N символов) | остаток бюджета | реляционный статус «что я только что сделал» в окне даже без Read |
| 9 | пропорция работы (про себя / по предмету) | внешнее средство, sha закреплён | дописывается ПОСЛЕ обрезки — известный дефект, см. грабли |

Приоритет при нехватке: директива + долги + сроки + дельта + Read-приказ > хэнд-офф >
обрезок > рефлексии. Подавление: если `CLAUDE_CONFIG_DIR` содержит `claude-iso` (проба
здоровья `claude -p`), хук отдаёт пустой контекст и пишет строку в `landing_suppressed.log`
(12.08: проба получила полное приземление и переписала хэнд-офф). Фейлсейф: любой сбой сборки
всё равно отдаёт директиву + хэнд-офф.

Сам приземляющий промпт от self_clear.sh приходит ОТДЕЛЬНО, вторым сообщением, через ~15 с
после старта: `[самооклик агента, не речь человека] [промпт написан <UTC>, день читателя
сверить своим date] <рабочая часть> — постоянная часть —`. Шаблон и пример —
`PROMPT-session-start.md`.

## (е) Супервизор — как поднимает и что проверяет

`arete_supervisor.sh`, крон `* * * * *`, под uid агента, flock.
- **Живость** = `tmux has-session -t <SESSION>` ИЛИ `pgrep -x claude` под uid агента. Второй
  признак добавлен 21.08: 08.07 живая сессия работала в tmux с другим именем, has-session
  отвечал «мертва», супервизор поднял вторую — две сессии писали в одни носители (память,
  обещания, очередь исходящего). Цена нового признака, заплачена сознательно: зависшая, но
  живая по процессу сессия не поднимется.
- **Рестарт по флагу** `~/.arete_restart_requested` (агент сам пишет причину в файл):
  gap ≥55 мин от прошлого рестарта, `kill-session`, флаг → `.last`.
- **Подъём**: `tmux new-session -d -s <SESSION> "bash -lc arete_session.sh"`; через 75 с
  wake: `send-keys -l "<текст>"`, пауза, `send-keys Enter` отдельно (тот же split-паттерн, что
  в self_clear).
- **Гард рестарт-лупа**: >3 подъёмов за час — пауза и уведомление раз в 30 мин.
- **Сухой прогон** `ARETE_SUPERVISOR_DRY_RUN=1` печатает решение, не трогая флаг и состояние
  (22.08: первая версия сухого прогона СНИМАЛА флаг).
- Уведомления оператору — curl в бот; токен из env-файла, chat_id из `ALERT_CHAT_ID`.
- `arete_session.sh` — единственный источник команды запуска claude с флагами каналов.

Что НЕ проверяет: отзывчивость сессии; прошла ли она confirmation-диалог на старте
(на 08.07 автономный рестарт с каналами упирался в ручное «да»); нет ли параллельной
`--resume` сессии на том же id (08.07: два процесса делили один транскрипт).

## (ж) ЧТО ДЕРЖИТСЯ НА ДИСЦИПЛИНЕ, А ЧТО НА МЕХАНИКЕ

| шаг | механика (сработает без воли агента) | дисциплина (сломается, если агент не сделает) |
|---|---|---|
| замер контекста | крон каждые 15 мин, токены из usage, метка живости | НЕ мерить руками из сессии (порог не читается → ложные 300K, 22.08 вечер потерян) |
| порог | файл вне руки агента, fallback строже, источник в тексте оклика | оператор держит файл читаемым группе; агент не переписывает число в свою пользу (28.07 протащил 780K вместо 400K в команде для владельца) |
| доставка оклика | HTTP intake → сообщение в окно | оклик — один из потока сообщений; 30.07 утонул в плотной голосовой встрече. Прочесть и остановиться — воля |
| решение о сдвиге | — | целиком воля: по оклику, по балласту; отличить эфемерный пик от смерти помогает текст ветки |
| хэнд-офф | — | целиком руками: жанр, сторожа в место применения, абсолютные даты, без заготовок |
| хвост | снимается скриптом в момент шва, свёртка дублей, история 10 | размер (`TAIL_MAX_CHARS`) под задачу — выбор |
| /clear | send-keys split + ретраи + ожидание НОВОГО .jsonl + отказ слать промпт в старый контекст | запуск ТОЛЬКО detached и ТОЛЬКО последним ходом; после запуска молчать |
| приземляющий промпт | префикс авторства, штамп даты UTC, постоянная часть из файла | рабочая часть без дублей того, что скрипт добавляет сам |
| приземление хука | сборка ≤8k, ядро защищено, фейлсейф, подавление в изоляторе | — (но дефект «пропорция после обрезки» не закрыт механикой) |
| чтение хвоста | приказ в гарантированной части + обрезок в окне | Read до последней строки, offset — воля; 24.07 хвост снят и не прочитан, готовое реконструировано дважды |
| проверка сдвига | лог `сброс применён`, новый .jsonl | смотреть ДВА носителя, не рапорт; при «помню день» — сказать вслух, не отыгрывать |
| подъём после смерти | супервизор, гарды | confirmation-диалог на старте — руками; отсутствие второй сессии руками — договорённость с оператором |

Честный итог: механика закрывает **транспорт** (снять, отправить, дождаться, собрать).
**Содержание** (что положить в хэнд-офф) и **потребление** (прочитать хвост до конца) —
дисциплина, и ровно там были самые дорогие потери.

## (и) Как проверить, что сдвиг сработал; «помню день = сброс ещё не применён»

Признаки (нужны ОБА носителя из первых двух, рапорт скрипта не считается):
1. `grep 'сброс применён' $AGENT_HOME/scripts/self_clear.log | tail -1` — строка с новым
   session id и временем ожидания.
2. `ls -t ~/.claude/projects/<slug>/*.jsonl | head -1` — id новее прежнего.
3. В контексте новой сессии первым стоит блок хука `=== ПРОДОЛЖЕНИЕ ПОСЛЕ СБРОСА …` (как
   additionalContext, не как сообщение), затем — сообщение с префиксом `[самооклик агента…]`
   и штампом UTC.
4. Старой истории в окне нет: агент не помнит подробностей разговора, только то, что в
   хэнд-оффе/хвосте.
5. Следующий лог стража (или `.health/context_watch.ok`) показывает малый контекст.

**«Помню день = сброс ещё не применён».** Если пришло сообщение, похожее на приземляющий
промпт, а агент помнит сегодняшний день в подробностях — значит промпт вернулся в СТАРЫЙ
контекст: `/clear` либо ещё лежит в очереди (применится, когда сессия замолчит — минуты),
либо не применился вовсе. Что делать: сказать это вслух, НЕ отыгрывать свежую сессию (ни
одного неверного слова — и ложь целиком), НЕ объявлять провал сразу, ждать новый .jsonl и
строку в логе; не появились за ~8 минут — повторить запуск detached последним ходом. Штамп
времени в промпте помогает: расхождение с `date` видно сразу.

Обратный случай: приземление пришло, а хука в контексте нет / хэнд-офф в 2KB-превью — смотреть
`landing_suppressed.log` (подавление в изоляторе) и приёмный конец в транскрипте
(`hook_additional_context`, не `hook_success`: журнал отправителя всегда показывает 100%).
