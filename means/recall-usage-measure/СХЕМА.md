# Что нужно на вход, чтобы повторить у себя

Двух источников достаточно. Формат условный — важны поля, не имена файлов.

## 1. Журнал подъёмов — `assoc_log.jsonl`, по записи на строку

    {"ts": "2026-07-03T12:35:11", "prompt": "…запрос…", "hits": ["имя_карточки", …]}

- `ts` — время подъёма (UTC);
- `hits` — идентификаторы того, что подняли. У меня это имена файлов памяти;
  у вас — id буллетов playbook. Важно лишь, чтобы по id восстанавливался ТЕКСТ.

## 2. Ходы агента — транскрипт сессии
Нужны ответы агента с меткой времени. Скрипт берёт первый ответ в окне **600 секунд**
после подъёма; окно — параметр, его стоит подбирать под свой цикл.

## 3. Корпус текстов поднимаемого
Нужен для idf: какие слова редкие. Без него «пересечение слов» меряет длину словаря,
а не совпадение по существу — эту ошибку я уже совершил и поймал нормировкой.

## Порядок прогона
1. собрать пары «подъём → следующий ход»;
2. посчитать долю пар с ≥3 редкими совпадениями — это сырое число;
3. **перемешать пары и посчитать ту же долю** — это контроль;
4. сравнивать только разницу. Сырое число само по себе не значит ничего.

## Где ломается чаще всего
- **id выбранного не сохраняется после компрессии** — тогда пары собрать не из чего,
  и нужна инструментация ДО замера. Это первое, что стоит проверить у себя;
- «завершился ли run» вместо «вошло ли знание» — так меряется успех прогона, а не польза
  конкретного куска памяти;
- контроль подменой (взять случайные карточки вместо перемешивания) — завышает вдвое.
